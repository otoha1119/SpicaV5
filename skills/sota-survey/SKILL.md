# sota-survey

ML研究上の問題に対して、既存手法を「古典的手法・デファクトスタンダード・SOTA研究・問題の再定義・異分野越境」の5系統から幅広く発散させ、定量的な生値比較・重み付きスコアリング・Pareto所見によって収束させ、2〜3件の推薦にまとめるためのスキル。experiment-cycleでPivot（手法転換）が承認された直後、またはユーザーから手法調査を求められたときに使う。調査ノートは `docs/surveys/` に固定で残す。

## 手順

`templates/survey_note.md` を、このスキルのディレクトリを基準にした相対パスで読み、そのテンプレートの構成（定式化→発散→収束→推薦→棄却記録）に従って `docs/surveys/<YYYYMMDD>_<slug>.md` を新規作成する。

1. **定式化**：テンプレート「1. 問題の定式化」の各項目（入出力、ハード制約、交換可能な目標、成功指標）をユーザーとのやり取りや対象コードから埋める。「現手法の上限とその根拠」欄は、必ず `docs/experiments/` 配下の実験記録（`EXP-<YYYYMMDD>-<seq>.md`）を根拠として引用し、該当する実験IDを明記する。根拠となる実験記録が見つからない場合は、推測で埋めずユーザーに現状（既存手法の性能上限や、なぜ調査が必要か）を確認してから記入する。
2. **発散**：テンプレート「2. 発散」のA〜Eの5系統それぞれに、最低1件ずつ候補を挙げる。E（越境）では、異分野が同型の問題をどう解いているかを調べ、対象問題の制約を1つ外して考えた上で、外した制約を戻しても成立するかを検証してから記載する。
3. **収束**：テンプレート「3. 収束」の3点セット（生値比較テーブル→重み付きスコアリング→Pareto所見）を順に埋める。
4. **推薦**：テンプレート「4. 推薦」に2〜3件を記載する。
5. **棄却記録**：発散・収束の過程で外した候補も、テンプレート「5. 棄却候補と理由」に理由付きで残す。「付録: 証拠」に一次情報の引用をまとめる。

## 証拠収集

- 検索クエリは英語で行う。日本語で調べると英語圏の一次情報（論文・実装・ベンチマーク）を取りこぼしやすいため。
- 対象プロジェクトに以下のスキルが導入済みであれば優先的に使う：
  - `paper-lookup`（文献API横断検索）
  - `literature-review`（系統的レビュー）
  - `research`（一次情報の深掘り）
- これらが導入されていない場合は、WebSearch・WebFetchで代替する。

## 規律

- 「SOTA」と主張する候補には、出典と確認日を必ず併記する。出典・確認日を示せない場合は「SOTA」と書かない。
- 実在や性能を検証できない論文・ライブラリ・実装は「未確認」フラグを付けて記載し、確認済みの情報と区別する。
- 証拠の引用は英語原文のまま行い、翻訳しない。一方で要約・結論・推薦などノートの地の文は日本語で書く（手法名・専門用語は無理に和訳しない）。
- 実装が簡単・枯れている・単純であるという理由だけで候補を不利に扱わない。単純で要件を満たす候補は、複雑な候補と対等に比較する。
- 収束の過程で外した候補も棄却理由とともに記録に残し、検討した事実自体を消さない。

## 定量比較

「3. 収束」は以下の3点セットを必ずこの順で行う。

1. **生値比較テーブル**：候補ごとに精度・速度・実装コスト・データ要件・成熟度・変更クラス・出典と確認日を記入する。精度は評価に使われたデータセット条件を併記する（データセットが異なる数値をそのまま並べない）。裏付けが取れない値は空欄にせず「未確認」と明記する。変更クラスは「チューニング / アルゴリズム / アーキテクチャ / 問題再定義」のいずれかを選ぶ。
2. **重み付きスコアリング**：精度・速度・実装コスト・データ要件・成熟度の各軸に重みを付けてスコア化する。重みの値と、その重みをその値にした理由の両方を必ずノート内に明示的に宣言する（暗黙の重み付けをしない）。
3. **Pareto所見**：速度・精度・コストの支配関係（ある候補が他の候補を全軸で上回っていて、その候補を選ぶ理由がなくなっていないか）を確認し、単純で十分な選択肢を不利に扱わないように所見をまとめる。

## 推薦

- 推薦は2〜3件とし、異なる原理の手法を混ぜる。同一手法のパラメータ違いだけを複数推薦として並べることはしない。
- 各推薦には以下を書く。
  - **最小反証実験**：experiment-cycleの事前登録形式と同じ4項目（仮説・反証条件・Go/No-Go基準・タイムボックス）で書く。これにより、この推薦が採用された際、experiment-cycleが作成する実験ログの「事前登録」セクションへそのまま転記できる。
  - **撤退ライン**：この推薦を諦めて次善候補または再調査に切り替える条件。
  - **移行・ロールバック方針**：採用した場合の移行手順と、うまくいかなかった場合に元の手法へ戻す方針。
- 対象プロジェクトに `docs/research-config.md` があれば「候補PoCあたりの資源上限」を最小反証実験のタイムボックス設定の上限として参照する。
